% background intro
\bigskip

This work studies spectrum sensing for a prospective CubeSat cognitive radio (CR).  For the M-QAM-SRRC signal model, the receiver searches a specified grid of candidate symbol rates and center frequencies and uses cyclostationary feature detection (CFD) to distinguish modeled signals from noise.  A spectral correlation analyzer (SCA) realizes this detector.  Conventional FFT-based SCAs obtain high throughput by evaluating many spectral channels in parallel.  Their implementations buffer blocks of complex samples and intermediate transform results, so storage grows with both the capture length and the number of selected channels.  This memory can compete with limited on-chip FPGA block RAM (BRAM) in a CubeSat-class implementation.

BRAM capacity is therefore a central design constraint.  Reducing buffered storage improves fit within on-chip memory, while sample-by-sample time-domain processing trades the parallel throughput of an FFT-based analyzer for a deeply pipelined data path.  The application focuses on detecting the symbol rate and center frequency of M-QAM-SRRC waveforms, allowing the candidate search to be optimized for those cyclic features.  For this blind symbol-rate--center-frequency estimator, we borrow the communications term \textit{streaming}.  Thus, this design will be referred to as the \textit{streaming SCA}, an FPGA architecture for resource-conscious signal processing.

\addcontentsline{toc}{section}{\quad \: 3.1 \quad Motivation}
\noindent 3.1  \quad Motivation

Orbital systems may use a single spacecraft, a constellation, or a distributed architecture such as a fractionated, clustered, or trailing formation.  Distributed architectures coordinate multiple spacecraft, and CubeSats are one relevant small-spacecraft platform \cite{bandyopadhyay-15}.

Crosslinks and relays create operating scenarios in which inter-satellite interference may need to be monitored.  Spectrum sensing is one candidate mechanism for detecting occupied channels and informing an interference-avoidance response.

As discussed in the previous chapter, SCAs estimate cyclic spectral structure that can be used for spectrum sensing \cite{spooner-92}.  Several efficient digital SCA realizations use FFTs, sample blocks, and intermediate arrays whose storage requirements can be substantial \cite{spooner-92,liang-20}.

For a concrete scaling example, an SSCA intermediate array with $N=2^{16}$ time samples and $N_p=32$ selected frequency channels contains $NN_p$ complex words \cite{spooner-92}.  At $16$ bits for each in-phase and quadrature component, or $32$ bits per complex word, that array alone requires $2^{16}\times32\times32=67{,}108{,}864$ bits, or $67.1\text{ Mbit}$, before control and buffering overhead.  The implementation targets a ZedBoard with an XC7Z020CLG484-1, which provides $4.9\text{ Mbit}$ of block RAM \cite{xilinx-ds190}.  The streaming architecture therefore replaces the large intermediate array with bounded pipeline state that fits the selected platform's memory budget.

\bigskip
\addcontentsline{toc}{section}{\quad \: 3.2 \quad The Streaming SCA}
\noindent 3.2  \quad The Streaming SCA

Let us assume that we wish to sense modeled waveforms present in a channel.  As discussed in Chapter II, the single-term CAF-DFT form can evaluate selected frequency candidates without a block FFT.  To create a low-memory design suitable for evaluation on the selected FPGA, we alter the CAF-DFT such that it:

\begin{itemize}
\item Evaluates only one pipelined $(v,k)$ pair at a time, called a point.  This is equivalent to one branch in Figure~\ref{fig:koch_sca}.  If our SCA is well designed, the branches can be reconfigured so that multiple instances can be used in parallel when the platform has extra resources.

\item Avoids a full-capture BRAM buffer.  A block-based realization buffers a capture so that every $(v,k)$ pair is evaluated on the same samples.  This design accepts a continuous input sample stream from the system-level data interface and evaluates successive candidate pairs over successive time intervals, reducing buffered storage for signals that remain stable over the search.

\item Targets FPGA implementation so that the estimator can use deterministic pipelines and configurable parallelism within the platform's resource budget.  Device qualification and mitigation are applied during system integration.

\item Evaluates nonzero cycle frequencies $\alpha\neq0$, which represent the cyclostationary features used by the detector; the zero-cycle-frequency case corresponds to the ordinary PSD.

\item Uses a fixed two-tap low-pass filter (LPF), corresponding to taps $[0.5,0.5]$.  Koch's evaluated carrier-frequency detector systematically shifts each segment, dynamically configures the LPF bandwidth to the target symbol rate, and evaluates the CAC at that rate \cite{koch-19}.  The streaming design is a serial hardware adaptation of that sweep; to avoid a reconfigurable coefficient bank, it uses the same two coefficients for every candidate.
\end{itemize}

The streaming SCA was modeled in MATLAB to produce Figure~\ref{fig:qam_srrc_rs}.  The two generated components are scaled so that a single receiver-noise realization gives the requested $E_b/N_0$ values of $14$ dB and $9$ dB.  A common automatic-gain-control (AGC) scale factor then limits the composite waveform without changing either component's carrier-to-noise ratio.  On the $10$ kHz center-frequency grid, the row maxima occur at the transmitted center frequencies of $50$ kHz and $100$ kHz; their test-statistic-to-threshold ratios are $9.29$ and $2.47$, respectively.  These numerical values are reproducible because the model fixes its random-number seed.  The executable MATLAB model is imported directly in Appendix A.

In exchange for this low memory use, the processing time is increased.  With one $(v,k)$ point evaluated at a time, no backpressure, and a sustained rate of one valid sample per clock, an exhaustive search over $N_v$ symbol-rate candidates and $N_k$ center-frequency candidates requires approximately $NN_vN_k$ sample clocks, in addition to pipeline and control overhead.  For fixed search spans, the processing delay therefore increases with capture length and with the number of candidates:

\begin{itemize}
\item Symbol-rate step size: A smaller step produces more symbol-rate candidates and a longer search, whereas a larger step coarsens the grid and can increase parameter mismatch.

\item Center-frequency step size: A smaller step produces more center-frequency candidates and a longer search, whereas a larger step coarsens the grid and can increase parameter mismatch.

\item Capture length $N$: A larger capture takes longer to process but provides a longer observation interval; a smaller capture reduces delay at the cost of a less stable finite-record estimate.
\end{itemize}

\addcontentsline{toc}{section}{\quad \: 3.3 \quad Digital Design}
\noindent 3.3  \quad Digital Design

To describe the implementation of the streaming SCA as a digital circuit, we will walk through each component and its subcomponents.  The signal-processing datapath uses custom VHDL modules and selected-frequency arithmetic in place of a vendor FFT core.  MATLAB and Xilinx Vivado support modeling, simulation, synthesis, and implementation.  The tables define the configured external interfaces used by the architecture; propagation-only width and latency parameters remain internal to their corresponding pipeline stages.

The datapath uses an AXI4-Stream interface.  An input transfer occurs on a rising edge of \texttt{aclk} when both \texttt{s\_axis\_tvalid} and \texttt{s\_axis\_tready} are asserted; an output transfer occurs when both \texttt{m\_axis\_tvalid} and \texttt{m\_axis\_tready} are asserted.  While \texttt{m\_axis\_tready} is deasserted, the stage holds \texttt{m\_axis\_tdata}, \texttt{m\_axis\_tlast}, and \texttt{m\_axis\_tvalid} stable.  The upstream signal \texttt{s\_axis\_tready} indicates whether the stage can accept a sample.  In sample-preserving stages, \texttt{tdata}, \texttt{tvalid}, and \texttt{tlast} advance together.  At an integrate-and-dump boundary, every accepted input transfer contributes to the record state, and one aligned result is emitted with \texttt{m\_axis\_tvalid} and \texttt{m\_axis\_tlast} after the terminal input reaches that boundary.

The configured center-frequency-estimator datapath uses \texttt{TAP\_COUNT=2}, giving the moving-average response $h=[0.5,0.5]$.  In the supplied source, this datapath is entity \texttt{SingleTermCFE} in \texttt{CenterFrequencyEstimator.vhd}, and its selected-frequency symbol-rate stage is entity \texttt{SingleTermSRE}.  The arithmetic and control interfaces are implemented as custom VHDL pipelines.  The discussion occasionally refers to VHDL functions, such as \texttt{resize()}; however, the signal-processing description is otherwise language-agnostic.

\addcontentsline{toc}{subsection}{\quad 3.3.1 \quad Center-Frequency Estimator}
\noindent 3.3.1  \quad Center-Frequency Estimator

% the purpose of the module
The purpose of the center-frequency estimator is to produce a test-statistic surface over the symbol-rate--center-frequency candidate pairs.  Let $v$ and $k$ index user-defined candidate arrays with physical frequencies $\alpha_v$ and $f_k$, respectively.  For an input sequence $x[n]$, define

\begin{equation*}
z_k[n]=\left[\left(x[\cdot]\mathrm{e}^{-\mathrm{j}2\pi f_k(\cdot)/F_s}\right)\ast h[\cdot]\right][n],
\qquad
\widehat{C}_{x}(\alpha_v,f_k)=\frac{1}{N}\sum_{n=0}^{N-1}|z_k[n]|^{2}\mathrm{e}^{-\mathrm{j}2\pi\alpha_v n/F_s}.
\end{equation*}

The center-frequency control word configures a downconverting local oscillator for the factor $\mathrm{e}^{-\mathrm{j}2\pi f_k n/F_s}$.  Next, an LPF module smooths the mixed signal with the fixed taps $[0.5,0.5]$.  The symbol-rate estimator then evaluates the zero-lag CAF coefficient $\widehat{C}_{x}(\alpha_v,f_k)=\widehat{R}_{z_k}^{\alpha_v}[0]$, and the final magnitude-squared operation produces one point of the test statistic, $T_x(v,k)=|\widehat{C}_{x}(\alpha_v,f_k)|^{2}$.  Thus, $v$ and $k$ are candidate-array indices rather than frequencies themselves.  As explained in Chapter II, $\widehat{C}_{x}$ is interpreted as the filter-localized cyclic statistic associated with $f_k$.

For each candidate pair $(\alpha_v,f_k)$, the controller holds both frequency-control words constant for one $N$-sample record.  Each accepted sample is downconverted by $f_k$, filtered by $h[n]$, converted to a nonnegative magnitude-squared value, mixed by $\alpha_v$, and accumulated.  The final sample is included exactly once in the record result.  After normalization by $N$, the magnitude squared of the complex sum forms $T_x(v,k)$.  Acceptance of the transfer carrying \texttt{s\_axis\_tlast} clears the FIR delay at the record boundary.  Once the resulting \texttt{m\_axis} transfer has been accepted, the controller applies the next candidate pair and accepts its first sample with zero FIR state.

The thesis configuration specializes the NCO to a 16-bit phase accumulator with two quadrant bits and a 14-bit quarter-wave lookup address.  An integer frequency-control word $K_{\mathrm{FCW}}$ represents $K_{\mathrm{FCW}}\,F_s/2^{16}$ modulo $F_s$, giving a $15.2588$-Hz quantum at $F_s=1\text{ MHz}$.  Signed center-frequency codes represent $[-F_s/2,F_s/2-F_s/2^{16}]$.  Unsigned symbol-rate codes 0 through 32767 retain their positive interpretation at the signed NCO boundary, while code 32768 represents the aliased Nyquist endpoint.  The oscillator advances one control-word step on every accepted input transfer, so oscillator phase index and sample index advance together even when backpressure pauses the stream.  If the cycle-frequency candidates are restricted to an $N$-point DFT grid, MATLAB's one-based index satisfies $\alpha_v=(v-1)F_s/N$; the NCO can also evaluate candidates off that grid subject to its $15.2588$-Hz quantization.

\addcontentsline{toc}{subsection}{\quad 3.3.2 \quad Symbol-Rate Estimator}
\noindent 3.3.2  \quad Symbol-Rate Estimator

% purpose
The purpose of the symbol-rate estimator is to estimate the correlation between a waveform and the candidate symbol-rate cycle frequency $\alpha_v$.  Its computation is the finite-record CAF estimate evaluated at $\tau=0$:

\begin{equation*}
\widehat{R}_{x}^{\alpha_v}[0] = \frac{1}{N} \sum_{n=0}^{N-1} |x[n]|^{2} \mathrm{e}^{-\mathrm{j}2\pi\alpha_v n/F_s}.
\end{equation*}

The instantaneous-power module computes the nonnegative sequence $p_x[n]=|x[n]|^{2}$.  The selected-frequency Fourier-sum evaluator then computes the displayed zero-lag CAF expression at $\alpha_v$.  For Q1.15 input components, $p_x[n]=x_{\mathrm{I}}[n]^2+x_{\mathrm{Q}}[n]^2$ lies in $[0,2]$ and has a full-precision unsigned 32-bit representation with 30 fractional bits.  The format boundary into the signed Fourier mixer therefore preserves the magnitude bit by either zero-extending into a wider signed word or by explicitly rescaling and saturating.  One conforming 16-bit mapping is a saturated Q1.15 representation of $p_x[n]/2$.  This scales the resulting complex CAF coefficient by one half and the downstream magnitude-squared statistic and matching threshold by one quarter; those factors are carried consistently.  Every power sample remains nonnegative throughout the interface.

\addcontentsline{toc}{subsection}{\quad 3.3.3 \quad Selected-Frequency Fourier-Sum Evaluator}
\noindent 3.3.3  \quad Selected-Frequency Fourier-Sum Evaluator

% purpose
The VHDL entity \texttt{SingleTermDft} implements a selected-frequency Fourier-sum evaluator.  It evaluates a finite-record Fourier sum at one selected physical frequency $f_0$ at a time:

\begin{equation*}
\widehat{x}(f_0)=\frac{1}{N}\sum_{n=0}^{N-1}x[n]\mathrm{e}^{-\mathrm{j}2\pi f_0n/F_s}.
\end{equation*}
	
The corresponding normalized $N$-point DFT coefficient $\widehat{x}[\ell]$ is the special case $f_0=\ell F_s/N$ for the zero-based bin $0\leq\ell<N$.  The oscillator frequency-control word selects $f_0$, the mixer forms the complex products $x[n]\mathrm{e}^{-\mathrm{j}2\pi f_0n/F_s}$, and separate real and imaginary accumulators sum exactly $N$ products.  The final marked sample is included before the completed sums are normalized, quantized, and emitted.  The quarter-wave lookup-table reconstruction can introduce a constant NCO initial-phase factor, but that factor cancels in the final magnitude squared.  For the symbol-rate estimator, $f_0=\alpha_v$; when the candidates lie on the DFT grid, $\ell=v-1$ under MATLAB's one-based indexing.

\addcontentsline{toc}{subsection}{\quad 3.3.4 \quad Frequency Mixer}
\noindent 3.3.4  \quad Frequency Mixer

% purpose
Frequency translation is performed by multiplying the input by a complex local oscillator generated by a numerically controlled oscillator (NCO).  For a positive-frequency component at $f_1$, multiplication by the downconverting oscillator at $f_{\mathrm{LO}}$ gives

\begin{equation*}
\mathrm{e}^{\mathrm{j}2\pi f_1n/F_s}\,\mathrm{e}^{-\mathrm{j}2\pi f_{\mathrm{LO}}n/F_s}
=\mathrm{e}^{\mathrm{j}2\pi(f_1-f_{\mathrm{LO}})n/F_s}.
\end{equation*}

When $f_{\mathrm{LO}}=f_1$, the component is translated to zero frequency.  The implementation generates the oscillator with a phase accumulator and a sine/cosine lookup table; the frequency-control word sets its phase increment.  The phase accumulator advances on each accepted \texttt{s\_axis} transfer, so a stalled transaction preserves both the sample and its corresponding oscillator phase and the phase index remains aligned with the consecutive sample index $n$.

\addcontentsline{toc}{subsection}{\quad 3.3.5 \quad Low-Pass Filter}
\noindent 3.3.5  \quad Low-Pass Filter

% purpose
A finite impulse response (FIR) filter has a finite-duration impulse response.  Filter coefficients are calculated from the desired properties of the filter in MATLAB or Python.  An $L$-tap FIR implements the convolution sum

\begin{equation*}
y[n]=\sum_{m=0}^{L-1}b[m]x[n-m].
\end{equation*}

Here, $b[m]$ are the $L$ coefficients, and $x[n]$ is the input sequence.  A causal FIR with $L$ taps has order $L-1$.  This design uses the two-tap, first-order moving-average low-pass filter $b[0]=b[1]=0.5$.  Each candidate record uses the zero-state convention $x[-1]=0$.  Within a record, the delay stores the preceding accepted sample.  Acceptance of the transfer carrying \texttt{s\_axis\_tlast} marks the record boundary and clears the one-sample delay before the next record's first transfer.  No state from one candidate therefore enters the next.

\addcontentsline{toc}{subsection}{\quad 3.3.6 \quad Instantaneous Power}
\noindent 3.3.6  \quad Instantaneous Power

% purpose
This module computes the pointwise magnitude squared of a complex sample.  It supplies the $\tau=0$ product $x[n]x^{*}[n]$ used by the zero-lag ACF and CAF:

\begin{align*}
p_x[n] &= x[n]x^{*}[n] \\
       &= |x[n]|^{2} \\
       &= \Real(x[n])^{2}+\Imag(x[n])^{2}.
\end{align*}

The real and imaginary components are squared in parallel and then added.  This pointwise identity is not Parseval's theorem, which instead relates a sum or integral of squared magnitudes in the time domain to one in the frequency domain.

\addcontentsline{toc}{subsection}{\quad 3.3.7 \quad Complex Multiplier}
\noindent 3.3.7  \quad Complex Multiplier

Let the two complex operands be $x_A[n]=x_{A,\mathrm{I}}[n]+\mathrm{j}x_{A,\mathrm{Q}}[n]$ and $x_B[n]=x_{B,\mathrm{I}}[n]+\mathrm{j}x_{B,\mathrm{Q}}[n]$, and let $y[n]=x_A[n]x_B[n]$.  The in-phase and quadrature components of the product are

\begin{align*}
y_{\mathrm{I}}[n] &= x_{A,\mathrm{I}}[n] \, x_{B,\mathrm{I}}[n]-x_{A,\mathrm{Q}}[n] \, x_{B,\mathrm{Q}}[n], \\
y_{\mathrm{Q}}[n] &= x_{A,\mathrm{I}}[n] \, x_{B,\mathrm{Q}}[n]+x_{A,\mathrm{Q}}[n] \, x_{B,\mathrm{I}}[n].
\end{align*}

Thus, the multiplication of $x_A[n]$ and $x_B[n]$ requires four real multiplications, one real addition, and one real subtraction.

\addcontentsline{toc}{subsection}{\quad 3.3.9 \quad Accumulator}
\noindent 3.3.9  \quad Accumulator

% purpose
The accumulator implements the running sum used by each single-frequency Fourier evaluation and participates in the integrate-and-dump flow control between sample sets.  For a sequence whose first accepted sample has local index $n=0$, the recurrence is

\begin{equation}
s[n] = \left\{
       \begin{array}{ll}
         x[n],          & n=0, \\
         s[n-1]+x[n],   & n>0
      \end{array}
      \right.
      .
\end{equation}

\noindent Here, $x[n]$ is an input sample and $s[n]$ is the running sum within the current record.  The module itself is real-valued; the Fourier-sum evaluator instantiates separate accumulators for the in-phase and quadrature components.  On each accepted input transfer, the adder first forms $s_{\mathrm{next}}=s+x[n]$, with the first sample using a cleared stored sum.  An ordinary sample stores $s_{\mathrm{next}}$.  A sample carrying \texttt{s\_axis\_tlast} stores no residual value: it emits the normalized $s_{\mathrm{next}}$, asserts \texttt{m\_axis\_tvalid} and \texttt{m\_axis\_tlast}, and clears the stored sum for the next record.  This end-of-record convention includes each of the $N$ samples exactly once.

For a signed $W$-bit input and a record of $N$ samples, the full-range accumulator width is

\begin{equation*}
W_{\mathrm{acc}}=W+\ceil{\log_2 N}.
\end{equation*}

A 16-bit, 4096-sample configuration therefore uses a 28-bit sum and a 12-bit normalization shift.  A 16-bit, 65,536-sample configuration uses a 32-bit sum and a 16-bit shift.  For power-of-two $N$, a sign-aware rounding adjustment followed by selection of the corresponding upper bits implements rounded division by $N$; for other record lengths, normalization uses a constant reciprocal or divider with guard bits before the same rounding and saturation stage.  The configured \texttt{N\_SAMPLES} value establishes the counter limit, accumulator width, and normalization factor, while \texttt{s\_axis\_tlast} is asserted with count $N-1$ as the protocol-level end-of-record tag.  A clock without an accepted input transfer leaves the sample-indexed state unchanged, and a pending output remains stable until accepted on \texttt{m\_axis}.
