% background intro
\bigskip

This work studies spectrum sensing for a prospective CubeSat cognitive radio (CR).  Within the deliberately limited M-QAM-SRRC model used in this thesis, the receiver searches a specified grid of candidate symbol rates (SRs) and center frequencies (CFs) and uses cyclostationary feature detection (CFD) to distinguish modeled signals from noise.  A spectral correlation analyzer (SCA) can realize this detector.  Conventional FFT-based SCAs obtain high throughput by evaluating many spectral channels in parallel.  Their implementations buffer blocks of complex samples and intermediate transform results, so storage grows with both the capture length and the number of retained channels.  This memory can compete with limited on-chip FPGA block RAM (BRAM) in a CubeSat-class implementation.

BRAM capacity is therefore a central design constraint.  Reducing buffered storage improves fit within on-chip memory, while sample-by-sample time-domain processing trades the parallel throughput of an FFT-based analyzer for a deeply pipelined data path.  To limit the resulting search time, the application is restricted to detecting the SR and CF of M-QAM-SRRC waveforms rather than estimating every cyclic feature of an arbitrary waveform.  For this blind SR--CF estimator, we borrow the communications term \textit{streaming}.  Thus, this design will be referred to as the \textit{streaming SCA}.  It is an FPGA architecture study, not a flight-qualified implementation.

\addcontentsline{toc}{section}{\quad \: 3.1 \quad Motivation}
\noindent 3.1  \quad Motivation

Orbital systems may use a single spacecraft, a constellation, or a distributed architecture such as a fractionated, clustered, or trailing formation.  Distributed architectures coordinate multiple spacecraft, and CubeSats are one relevant small-spacecraft platform \cite{bandyopadhyay-15}.

Crosslinks and relays create operating scenarios in which inter-satellite interference may need to be monitored.  Spectrum sensing is one candidate mechanism for detecting occupied channels and informing an interference-avoidance response.

As discussed in the previous chapter, SCAs estimate cyclic spectral structure that can be used for spectrum sensing \cite{spooner-92}.  Several efficient digital SCA realizations use FFTs, sample blocks, and intermediate arrays whose storage requirements can be substantial \cite{spooner-92,liang-20}.

For a concrete scaling example, an SSCA intermediate array with $N=2^{16}$ time samples and $N_p=32$ retained frequency channels contains $NN_p$ complex words \cite{spooner-92}.  At $16$ bits for each in-phase and quadrature component, or $32$ bits per complex word, that array alone requires $2^{16}\times32\times32=67{,}108{,}864$ bits, or $67.1\text{ Mbit}$, before control and buffering overhead.  The recovered 2021 component design reports and project-recreation scripts consistently identify the intended development platform as a ZedBoard with an XC7Z020CLG484-1.  That device provides $4.9\text{ Mbit}$ of block RAM \cite{xilinx-ds190}, so this particular array would not fit wholly in its BRAM without reducing the stored data or changing the architecture.  This establishes the documented component-development target; it does not establish the provenance of the experiment-level resource counts in Chapter IV, whose top-level synthesis report is unavailable.

\addcontentsline{toc}{section}{\quad \: 3.2 \quad The Streaming SCA}
\noindent 3.2  \quad The Streaming SCA

Let us assume that we wish to sense modeled waveforms present in a channel.  As discussed in Chapter II, the single-term CAF-DFT form can evaluate selected frequency candidates without a block FFT.  To create a low-memory design suitable for evaluation on the selected FPGA, we alter the CAF-DFT such that it:

\begin{itemize}
\item Evaluates only one pipelined $(v,k)$ pair at a time, called a point.  This is equivalent to one branch in Figure~\ref{fig:koch_sca}.  If our SCA is well designed, the branches can be reconfigured so that multiple instances can be used in parallel when the platform has extra resources.

\item Avoids a full-capture BRAM buffer.  A block-based realization buffers a capture so that every $(v,k)$ pair is evaluated on the same samples.  This design instead accepts a continuous input sample stream without retaining the full capture; ADC interfacing is outside the module.  Consequently, different candidate pairs can observe different time intervals, but the design reduces buffered storage when the signal is sufficiently stable over the search.

\item Targets FPGA implementation so that the estimator can use deterministic pipelines and configurable parallelism within the platform's resource budget.  FPGA implementation alone does not establish radiation tolerance; device qualification and mitigation are separate design considerations.

\item Does not evaluate the zero-cycle-frequency case $\alpha=0$, which corresponds to the ordinary PSD rather than a nontrivial cyclostationary feature.

\item Uses a fixed two-tap low-pass filter (LPF), corresponding to taps $[0.5,0.5]$.  Koch's evaluated carrier-frequency detector systematically shifts each segment, dynamically configures the LPF bandwidth to the target symbol rate, and evaluates the CAC at that rate \cite{koch-19}.  The streaming design is a serial hardware adaptation of that sweep; to avoid a reconfigurable coefficient bank, it uses the same two coefficients for every candidate.
\end{itemize}

The streaming SCA was modeled in MATLAB to produce Figure~\ref{fig:qam_srrc_rs}.  The two generated components are scaled so that a single receiver-noise realization gives the requested $E_b/N_0$ values of $14$ dB and $9$ dB.  A common automatic-gain-control (AGC) scale factor then limits the composite waveform without changing either component's carrier-to-noise ratio.  On the $10$ kHz CF grid, the row maxima occur at the transmitted CFs of $50$ kHz and $100$ kHz; their test-statistic-to-threshold ratios are $9.41$ and $2.16$, respectively.  These numerical values are reproducible because the model fixes its random-number seed.  The executable MATLAB model is imported directly in Appendix A.

In exchange for this low memory use, the processing time is increased.  With one $(v,k)$ point evaluated at a time, no backpressure, and a sustained rate of one valid sample per clock, an exhaustive search over $N_v$ SR candidates and $N_k$ CF candidates requires approximately $NN_vN_k$ sample clocks, in addition to pipeline and control overhead.  For fixed search spans, the processing delay therefore increases with capture length and with the number of candidates:

\begin{itemize}
\item SR step size: A smaller step produces more SR candidates and a longer search, whereas a larger step coarsens the grid and can increase parameter mismatch.

\item CF step size: A smaller step produces more CF candidates and a longer search, whereas a larger step coarsens the grid and can increase parameter mismatch.

\item Capture length $N$: A larger capture takes longer to process but provides a longer observation interval; a smaller capture reduces delay at the cost of a less stable finite-record estimate.
\end{itemize}

\addcontentsline{toc}{section}{\quad \: 3.3 \quad Digital Design}
\noindent 3.3  \quad Digital Design

To describe the implementation of the streaming SCA as a digital circuit, we will walk through each component and its subcomponents.  The documented signal-processing datapath uses custom VHDL modules rather than a vendor FFT core.  MATLAB and Xilinx Vivado were nevertheless used for modeling and implementation, and inferred device resources can affect portability.  The tables summarize the configured documentation interface rather than reproducing every literal entity generic or port name; in particular, some propagation-only width and latency generics are omitted, and several arithmetic names are shortened.  The port tables retain the RTL's ready/valid names, but the recovered modules form fixed-latency pipelines rather than a fully elastic ready/valid interface: several data paths and state machines do not stall when \texttt{SampleOutReady} is low.  The characterization therefore assumes continuous, non-backpressured operation with one valid sample per clock and the downstream path held ready.  Supporting arbitrary bubbles or backpressure requires revised control logic and re-verification.

The recovered archive does not contain the exact thesis-era source revision.  Its Git index identifies the later revision \texttt{1972ccba} from July 5, 2022, but the extracted worktree contains tracked divergences and its pre-clone Git object pack is missing, preventing reconstruction of the 2021 history.  A contemporaneous CFE design report explicitly documents a two-tap configuration in which \texttt{TAP\_COUNT=2} produces the coefficients $[0.5,0.5]$.  By contrast, the active later source uses a 41-tap, 128-bank filter.  The archive therefore substantiates the thesis configuration's design intent but cannot establish bit-true conformance of the historical VHDL.  It also contains a later, incomplete top-level wrapper with an FFT-based symbol-rate preprocessor; that unfinished development branch is outside the implementation characterized here.  The discussion occasionally refers to VHDL functions, such as \texttt{resize()}; however, the signal-processing description is otherwise language-agnostic.

\addcontentsline{toc}{subsection}{\quad 3.3.1 \quad Center Frequency Estimator}
\noindent 3.3.1  \quad Center Frequency Estimator

% the purpose of the module
The purpose of the center frequency estimator (CFE) is to produce a test-statistic surface over the SR--CF candidates.  Let $v$ and $k$ index user-defined candidate arrays with physical frequencies $\alpha_v$ and $f_k$, respectively.  For an input sequence $x[n]$, define

\begin{equation*}
z_k[n]=\left[\left(x[\cdot]e^{-j2\pi f_k(\cdot)/F_s}\right)\ast h[\cdot]\right][n],
\qquad
\widehat{C}_{x}(\alpha_v,f_k)=\frac{1}{N}\sum_{n=0}^{N-1}|z_k[n]|^{2}e^{-j2\pi\alpha_v n/F_s}.
\end{equation*}

The center-frequency control word configures a downconverting local oscillator for the factor $e^{-j2\pi f_k n/F_s}$.  Next, in the thesis configuration, an LPF module smooths the mixed signal with the fixed taps $[0.5,0.5]$.  The SRE then evaluates the zero-lag CAF coefficient $\widehat{C}_{x}(\alpha_v,f_k)=\widehat{R}_{z_k}^{\alpha_v}[0]$, and the final magnitude-squared operation produces one point of the test statistic, $T_x(v,k)=|\widehat{C}_{x}(\alpha_v,f_k)|^{2}$.  Thus, $v$ and $k$ are candidate-array indices rather than frequencies themselves.  As explained in Chapter II, $\widehat{C}_{x}$ is a filter-localized cyclic statistic, not literally the CSD value at $f_k$.

For a $W$-bit phase accumulator, a requested frequency $f$ is represented by the integer frequency-control word $\operatorname{round}(2^{W}f/F_s)$, modulo $2^{W}$, so the frequency quantum is $F_s/2^{W}$ and nearest-word error is at most half that quantum.  In the thesis configuration, $W=16$ and $F_s=1\text{ MHz}$, giving a quantum of approximately $15.26\text{ Hz}$.  The center-frequency port is signed to represent the range $-F_s/2$ through $F_s/2-F_s/2^W$.  The symbol-rate port is declared unsigned, but the surviving SRE passes its bit pattern to a signed NCO input; therefore only codes below $2^{W-1}$ retain a positive signed interpretation, while the $2^{W-1}$ code represents the equivalent Nyquist endpoint $-F_s/2$.  The searches in this thesis request rates no greater than $F_s/2$.  Although the RTL exposes width and lookup-phase generics, literal mixer bit slices mean the surviving implementation only evidences the $W=16$ configuration, and the lookup-phase generic is unused.  If the cycle-frequency candidates are restricted to an $N$-point DFT grid, MATLAB's one-based index satisfies $\alpha_v=(v-1)F_s/N$; the hardware frequency-control word also permits candidates that are not on that grid, subject to its quantization.

\addcontentsline{toc}{subsection}{\quad 3.3.2 \quad Symbol Rate Estimator}
\noindent 3.3.2  \quad Symbol Rate Estimator

% purpose
The purpose of the SR estimator (SRE) is to estimate the correlation between a waveform and the candidate SR cycle frequency $\alpha_v$.  Up to the fixed-point scaling and archived accumulator limitations described in Section~3.3.9, the target computation is the finite-record CAF estimate evaluated at $\tau=0$:

\begin{equation*}
\widehat{R}_{X}^{\alpha_v}[0] = \frac{1}{N} \sum_{n=0}^{N-1} |X[n]|^{2} e^{-j2\pi\alpha_v n/F_s}.
\end{equation*}

The instantaneous-power module is intended to compute $|X[n]|^{2}$.  The single-frequency Fourier-sum module then evaluates the displayed zero-lag CAF expression at $\alpha_v$.  The surviving SRE snapshot, however, configures the power block to retain unsigned bits 29 through 14 and then reinterprets that 16-bit word as signed at the DFT input.  For 16-bit inputs with 15 fractional bits, powers at or above approximately $0.5$ can therefore acquire a negative signed interpretation, and an ideal power of $1.0$ is carried by a discarded higher bit and maps to zero.  The unsigned-power-to-signed interface and truncation must be corrected and re-verified across the intended input range before the RTL can be considered bit-true to the displayed equation.

\addcontentsline{toc}{subsection}{\quad 3.3.3 \quad Discrete Fourier Transform}
\noindent 3.3.3  \quad Discrete Fourier Transform

% purpose
The DFT is used to perform frequency-domain analysis of discrete-time signals.  This implementation evaluates a finite-record Fourier sum at one selected physical frequency $f_0$ at a time:

\begin{equation*}
\widehat{X}(f_0)=\sum_{n=0}^{N-1}X[n]e^{-j2\pi f_0n/F_s}.
\end{equation*}
	
The standard $N$-point DFT coefficient $\widehat{X}[\ell]$ is the special case $f_0=\ell F_s/N$ for the zero-based bin $0\leq\ell<N$.  In the intended hardware operation, the oscillator frequency-control word selects $f_0$, the mixer forms the complex products $X[n]e^{-j2\pi f_0n/F_s}$, and the accumulator sums $N$ products.  The quarter-wave lookup-table reconstruction can introduce a constant NCO initial-phase factor, but that factor cancels in the final magnitude squared.  For the SRE, $f_0=\alpha_v$; when the candidates lie on the DFT grid, $\ell=v-1$ under MATLAB's one-based indexing.  Section~3.3.9 documents a boundary discrepancy in the surviving accumulator RTL.

\addcontentsline{toc}{subsection}{\quad 3.3.4 \quad Frequency Mixer}
\noindent 3.3.4  \quad Frequency Mixer

% purpose
Frequency translation is performed by multiplying the input by a complex local oscillator generated by a numerically controlled oscillator (NCO).  For a positive-frequency component at $f_1$, multiplication by the downconverting oscillator at $f_{\mathrm{LO}}$ gives

\begin{equation*}
e^{j2\pi f_1n/F_s}\,e^{-j2\pi f_{\mathrm{LO}}n/F_s}
=e^{j2\pi(f_1-f_{\mathrm{LO}})n/F_s}.
\end{equation*}

When $f_{\mathrm{LO}}=f_1$, the component is translated to zero frequency.  The implementation generates the oscillator with a phase accumulator and a sine/cosine lookup table; the frequency-control word sets its phase increment.  In the archived mixer RTL, the phase accumulator advances on every clock rather than only on accepted \texttt{SampleInValid} transactions.  The implemented model therefore assumes one accepted sample per clock.  If a low-valid clock represents a genuinely elapsed but unobserved sample interval, the phase advance is physically consistent but the accepted samples are no longer consecutively indexed as in the equations; if it represents a stalled sample, the phase update must instead be gated with the sample-accept event.

\addcontentsline{toc}{subsection}{\quad 3.3.5 \quad Low-Pass Filter}
\noindent 3.3.5  \quad Low-Pass Filter

% purpose
A finite impulse response (FIR) filter has a finite-duration impulse response.  Filter coefficients are calculated from the desired properties of the filter in MATLAB or Python.  An $L$-tap FIR implements the convolution sum

\begin{equation*}
Y[n]=\sum_{i=0}^{L-1}b[i]X[n-i].
\end{equation*}

Here, $b[i]$ are the $L$ coefficients, and $X[n]$ is the input sequence.  A causal FIR with $L$ taps has order $L-1$.  This design uses the two-tap, first-order moving-average low-pass filter $b[0]=b[1]=0.5$.

\addcontentsline{toc}{subsection}{\quad 3.3.6 \quad Instantaneous Power}
\noindent 3.3.6  \quad Instantaneous Power

% purpose
This module computes the pointwise magnitude squared of a complex sample.  It supplies the $\tau=0$ product $X[n]X^{*}[n]$ used by the zero-lag AF and CAF:

\begin{align*}
P_{X}[n] &= X[n]X^{*}[n] \\
          &= |X[n]|^{2} \\
          &= \Re\{X[n]\}^{2}+\Im\{X[n]\}^{2}.
\end{align*}

The real and imaginary components are squared in parallel and then added.  This pointwise identity is not Parseval's theorem, which instead relates a sum or integral of squared magnitudes in the time domain to one in the frequency domain.  For compactness, the following arithmetic-module tables use the documentation labels LEN\_A, LEN\_B, TRUNC, and RND for the VHDL generics \texttt{LengthA}, \texttt{LengthB}, \texttt{BitstoTrunc}, and \texttt{BitstoRound}, respectively.

\noindent 3.3.7  \quad Complex Multiplier

The product of two complex numbers can be expressed in terms of pairs of real and imaginary components as follows:

\begin{align*}
X_{1}[n]X_{2}[n]          &= (A+jB)(C+jD) \\
\Re \{X_{1}[n]X_{2}[n] \} &= AC-BD \\
\Im \{X_{1}[n]X_{2}[n] \} &= AD+BC.
\end{align*}

Here, the multiplication of complex values $X_{1}[n]X_{2}[n]$ simplifies to four real multiplications, one real addition, and one real subtraction.

\addcontentsline{toc}{subsection}{\quad 3.3.9 \quad Accumulator}
\noindent 3.3.9  \quad Accumulator

% purpose
The accumulator implements the running sum used by each single-frequency Fourier evaluation and participates in the integrate-and-dump flow control between sample sets.  For a sequence whose first accepted sample has local index $n=0$, the intended recurrence is

\begin{equation}
S[n] = \left\{
       \begin{array}{ll}
         X[n],          & n=0, \\
         S[n-1]+X[n],   & n>0
      \end{array}
      \right.
      .
\end{equation}

\noindent Here, $X[n]$ is an accepted input sample and $S[n]$ is the running sum within the current sequence.  The module itself is real-valued; the DFT instantiates separate accumulators for the in-phase and quadrature components.  The VHDL presents a fixed-width slice of its wider internal sum, so this step performs fixed-point scaling and truncation rather than an exact arithmetic division by $N$.  With the default $28$-bit sum and $16$-bit output, \texttt{Sum(27 downto 12)} is effectively a $12$-bit right shift; for $N=2^{16}$, it is not the $16$-bit shift corresponding to division by $N$.

The archived RTL and testbench do not implement the intended boundary recurrence exactly.  In the RTL, \texttt{N\_SAMPLES} is unused and the internal width \texttt{NORM\_FACTOR} is fixed at $28$ bits.  On a clock for which \texttt{SampleInLast} is asserted, \texttt{SampleOut} receives the pre-edge sum while the internal sum is loaded with the marked input.  Because the archived testbench asserts \texttt{SampleInLast} on sample $N-1$, the emitted closing sum excludes the marked sample, which instead seeds the next block.  Moreover, an overflow-free sum of $2^{16}$ arbitrary $16$-bit signed inputs requires $16+\log_2(2^{16})=32$ bits in the worst case, so the fixed $28$-bit internal width cannot guarantee overflow-free accumulation.  When \texttt{SampleInValid} is low, the process leaves \texttt{SampleInReady}, \texttt{SampleOutValid}, and \texttt{SampleOutLast} unchanged, so asserted status can persist rather than forming one-cycle handshake events.  The boundary, scaling, width, and interface-control logic therefore require correction and re-verification before the RTL is reused.
